--------------------------------------
1. Mount vendor and initialize firmware access if not already done:

   sudo mkdir -p /vendor
   sudo mount -o ro /dev/mapper/vendor_a /vendor
   echo /vendor/firmware | sudo tee /sys/module/firmware_class/parameters/path
   sudo chgrp video /dev/kgsl-3d0 /dev/ion
   sudo chmod 0660 /dev/kgsl-3d0 /dev/ion

FAILED INTEGRATION TESTS AND MEANING
------------------------------------
- A custom Gallium Freedreno build with freedreno-kmds=kgsl does not initialize
  EGL on Linux. KGSL Gallium/EGL support is tied to Mesa's Android platform;
  merely adding kgsl_dri.so does not create a usable Linux GBM/EGL backend.
- Phoc contains wlroots' Vulkan renderer, but a nested Wayland backend fails:
    Cannot create Vulkan renderer: no DRM FD available
- Direct wlroots Vulkan rendering requires a Vulkan physical device associated
  with the display DRM FD. KGSL Turnip is attached to /dev/kgsl-3d0, while the
  display is /dev/dri/card0; this route cannot join those devices as-is.
- vkcube --wsi wayland selects Turnip Adreno 610, then cannot negotiate a
  presentable format with the Pixman compositor. No accelerated surface was
  demonstrated.
- Keep WLR_RENDERER=pixman in both the greeter and authenticated Phosh session.
  Removing it returns login to the previously observed renderer failure.

WHY UBUNTU TOUCH IS NOT A DROP-IN FIX
-------------------------------------
Ubuntu Touch uses the Android/Halium graphics route: proprietary Android
Adreno EGL/GLES libraries behind libhybris, Android gralloc/KGSL services, and
Mir, in a glibc environment. Nura currently uses musl, Mesa, GBM, wlroots, and
Phoc. libhybris does not provide Phoc/wlroots with the GBM renderer it expects.
The ICD from the larger build-gl/install-gl build returned
VK_ERROR_INITIALIZATION_FAILED during a later headless enumeration; use the
minimal build ICD above as the known-good hardware-enumeration oracle.
The Ubuntu path proves this hardware and vendor firmware work, but reproducing
it requires adopting a compatible Halium/libhybris/Mir compositor path rather
than copying vendor libraries into the current process.

NEXT VIABLE ROUTES
------------------
1. Lowest kernel/userspace mismatch: reproduce Ubuntu Touch's glibc Halium +
   libhybris + Mir graphics stack, then determine whether Nura can run above
   that compositor. This is the literal Ubuntu path but a substantial UI-stack
   change.
2. Best long-term Phoc architecture: move to a kernel/display driver compatible
   with upstream Mesa's MSM DRM Freedreno path. This risks regressions in the
   downstream-only touchscreen, modem, Wi-Fi, and panel support.
3. High-risk engineering route: implement a wlroots renderer/allocator bridge
   between KGSL Turnip/Android gralloc and downstream MSM DRM. No existing
   bridge was found in the current stack.
