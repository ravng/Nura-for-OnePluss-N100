ONEPLUS NORD N100 (BILLIE2) NURA HARDWARE STATUS
================================================
Last updated: 2026-11-02

Status meanings
---------------
WORKING: physically demonstrated on this N100.
PARTIAL: low-level or experimental support works, but normal end-to-end use does not.
NOT WORKING: tested and confirmed unavailable.
UNTESTED: no result has been demonstrated; this does not prove failure.
WORKAROUND: usable through a temporary compatibility path.

WORKING
-------
- Boot to graphical Phrog login
- Login to Phosh desktop
- Display output
- Internal root storage
- USB Ethernet gadget
- SSH over USB at 172.16.42.1
- Volume-up button
- Volume-down button
- Power/wake button
- Internal speaker audio through ALSA, PulseAudio, and OS sound settings
  The billie2-audio OpenRC boot service automatically binds both physical
  WCD937x SoundWire endpoints, registers the Bengal ALSA card, applies the
  speaker route, and replaces PulseAudio Dummy Output with the real sink.

WORKING WITH WORKAROUND
-----------------------
- Touchscreen
  Works at login and in Phosh using the billie2-touch-resume kernel
  module/helper. A correct downstream DRM/Phoc unblank fix is still needed.
  Accelerated Mir does not yet receive usable touch coordinates; see the
  accelerated-touch entry under NOT WORKING.
- Wi-Fi interface and access-point scanning
  Native WLFW BDF/calibration QMI requests produce FW_READY; qcacld registers
  wlan0, p2p0, and wifi-aware0; NetworkManager listed nearby 2.4/5 GHz APs.
  Startup is currently manual because enabling billie2-wifi in the boot
  runlevel disrupts later boot services. Association and traffic are untested.




PARTIAL
-------
- GPU acceleration
  The exact Ubuntu Touch glibc/Halium/libhybris/Mir android2 path initializes
  HWC2, Qualcomm Adreno 610, and OpenGL ES 3.2 on the physical panel. An
  ABI-matched miral-kiosk rendered a visible weston-simple-shm Wayland client
  for five seconds at 720x1600 while SSH remained available. This is not yet
  integrated into the normal login/session; default Phosh remains Pixman.
  See GPU-STATUS.txt and gpu/halium/README.txt.

- Wi-Fi startup integration
  The native manual sequence is proven, but its OpenRC service must remain
  disabled until it can run without blocking or disrupting the boot runlevel.

- Cellular modem foundation
  Patched rmtfs, QRTR namespace, pd-mapper, modem QMI service enumeration, and
  IPA firmware loading work. SIM registration, telephony, SMS, and mobile data
  are not proven.

- IPA
  /vendor/firmware/ipa_fws.mdt loads through /dev/ipa, leaves reset, creates
  rmnet_ipa0, and resolves the IPA/WLAN SMMU mismatch.

- Audio
  The exact Ubuntu Touch/Android early-init ordering is required: load all
  downstream audio modules (including audio_wcd937x before
  audio_wcd937x_slave and audio_machine_bengal) before writing boot_adsp.
  Booting ADSP first leaves WCD937x RX SoundWire unenumerated with
  "SWR bus clsh detected". The corrected order binds both WCD937x endpoints,
  registers bengal-qrd-snd-card, exposes the physical RDAC controls, and lets
  the Android speaker mixer route drive both SIA81xx amplifiers. A 440 Hz
  direct ALSA tone and a 660 Hz PulseAudio tone were physically heard. The
  OpenRC boot service survived a full reboot; PulseAudio selected the real ALSA
  stereo fallback automatically, and output was confirmed in OS sound settings.
  Earpiece, microphones, headphones, and call audio remain unvalidated.

- Charging and battery reporting
  Kernel charger and battery events exist. Charging behavior, percentage
  accuracy, thermal behavior, and runtime have not been validated.

NOT WORKING
-----------
- Bluetooth controller
  The QTI Android Bluetooth HAL stays alive but does not register its binder
  service, so Bluebinder cannot create an HCI controller. The kernel also lacks
  CONFIG_BT_HCIUART and SERIAL_DEV_BUS; plain hciattach is not a safe fallback.
- Accelerated Mir touchscreen input
  Mir 1.8.2 evdev registers /dev/input/event1 after billie2_touch_resume is
  retriggered, but physical taps produce no EV_ABS coordinate events and
  weston-simple-touch remains unchanged. The driver emits only EV_SYN frames.

SAFETY / CURRENT LIMITATIONS
----------------------------
- Keep WLR_RENDERER=pixman in the default greeter and Phosh session.
- The accelerated Mir path is side-by-side under /opt/ut-root and is not a
  drop-in renderer for musl/Phoc/wlroots.
- Android LXC starts modem/Wi-Fi vendor services and remains unsafe as a
  general bring-up shortcut. The complete container replaces Nura's USB
  gadget; a modified container with configfs isolated entered CrashDump.
  Native audio now works without starting Android LXC.
- Never unload a partially initialized WLAN module live; a previous rmmod
  caused a kernel Oops.
- Keep billie2-wifi disabled at boot. FW_READY, wlan0, and scanning work when
  started manually, but synchronous OpenRC startup disrupts the boot sequence.
- Never boot /tmp/nura-billie2-no-rejuvenation.img; it entered CrashDump.

NEXT HARDWARE MILESTONES
------------------------
1. Determine why event1 emits only EV_SYN under Mir, then prove EV_ABS
   coordinates and visible weston-simple-touch trails.
2. Package the proven Halium/libhybris/Mir stack as a separate accelerated
   login session while retaining Pixman recovery.
3. Validate accelerated login, lock/unlock, apps, suspend/resume, and thermal
   stability.
4. Validate Wi-Fi association and traffic, then integrate non-blocking startup.
5. Implement a Bluetooth controller transport, then test discovery and pairing.
6. Validate earpiece, microphones, headphones, route switching, and call audio.
7. Test cameras, GPS, sensors, fingerprint, NFC, microSD, haptics, LEDs,
   flashlight, video decode, and remaining USB modes.
